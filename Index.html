这四条的限额取数服务自己算不出来（/api/health 只有进程内信息，整机配额要调面板子进程），所以按 devil user info 的输出手工写死在脚本的 HOST 里，不随部署自动更新；换主机或面板改限额时手改那一处即可。唯一的例外是「内存」那一格的用量：现取自 /api/health 的 rss_mb，那是本服务这一个进程的峰值 RSS，不是账户总占用（512 MB 是账户级上限），也不是整机内存；服务没上报时这一格显示「—」而不是补一个数。条形宽度、配色、超 100% 时「画到满格但数字照抄」全部由 pct 推导，页面里没有手填的百分比。

    

  


  

    
数据链路
浏览器直取官方源必被 CORS 拦，代理只解决可达性不解决跨域

    

      
页面 → 同源服务 http://127.0.0.1:8888 /api/{liquidity,crash,allocation}/* →（出口代理取服务端 config.ini 的 [proxy]，当前生效值见上方系统资源 · 出口代理一行）→ FRED / 美国财政部 / Yahoo / CNN / CNBC / multpl / GuruFocus / ccxt 行情源
上游分两条串行队列（官方数据 / 行情源），TTL 缓存 + 并发 single-flight；运行时参数一律 环境变量 > config.ini > 代码默认

      
未启动本地服务时本页与子页面的实时区全部显示失败标注——启动方法见项目根 start_app.bat 或 python main.py --open。
